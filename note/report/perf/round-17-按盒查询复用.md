# 轮次 17：按盒实体/玩家查询跨调用复用与谓词早退

> 日期：2026-10-05 ｜ 主题：内存 + CPU（实体/方块实体/红石热路径分配流失）
> 基线：轮次 16 收官（0.3.27）；本轮改动落库后以 0.3.28 发布
> 基准程序：[benchmark/src/bin/box_query_reuse.rs](../../../benchmark/src/bin/box_query_reuse.rs) ｜ 原始数据：[round17-box-query-reuse.json](round17-box-query-reuse.json)

## 1. 优化点与动机（生产可达性已验证）

延续「先验证生产可达，再落库」纪律。`World::get_entities_at_box` 每次
调用新建 `Vec<Arc<dyn EntityBase>>` 返回；桶索引路径内部
`ChunkedEntityIndex::query` 另建候选 Vec，再 `filter+collect` 出结果
Vec——单次调用最多三次堆分配。`get_players_at_box` 为一次
`filter+cloned+collect`。全仓 55 处调用点中，每 tick 无条件执行的热
路径包括：

- **漏斗方块实体**（每漏斗每 tick 搜索上方掉落物，自动化装置可达数千）；
- **实体推挤/搭载**（`entity/mod.rs` 每实体每 tick 3 实体查询 + 2 玩家
  查询）；
- **掉落物合并**（每掉落物每 tick）、**弹射物实体命中**（每飞行弹射物
  每 tick）、**区域效果云/潜影弹/唤魔者尖牙**、**漏斗矿车**；
- **压力板/绊线/比较器/探测铁轨/发射器/活塞/刷怪笼**（红石刻与方块
  实体 tick，且多数只需 `is_empty`/`len` 谓词）。

## 2. 改动内容

### 基础设施（`entity_index.rs` + `world/mod.rs`）

- `ChunkedEntityIndex::query` 拆出**重填模式** `query_into`（`result`
  清空重填、死弱引用剔除与空桶清理语义原样保留），`query` 改薄包装
  （测试与冷路径继续可用）；新增**谓词早退** `query_any`（任一满足
  即提前返回、全程不收集）。
- `World` 新增一族重填/谓词/门面方法：
  - `get_entities_at_box_into`：桶索引路径先 `query_into` 重填、再
    `retain` 原地按精确包围盒过滤（**单缓冲**，消去原第二 Vec）；
    大盒回退全表扫描逻辑不变。`get_entities_at_box` 保留为分配版
    兼容包装（插件 API 与冷路径调用点不受影响）。
  - `get_players_at_box_into` / 分配版包装，同理。
  - `has_entities_at_box` / `has_players_at_box`：谓词早退，
    **全程零分配**（`is_empty` 调用点的直答形态）。
  - `with_entities_at_box` / `with_players_at_box` /
    `with_entities_and_players_at_box`：线程局部暂存
    （`ENTITY_BOX_SCRATCH` / `PLAYER_BOX_SCRATCH`，const 初始化）
    + 闭包就地消费；联合查询顺序与旧「实体收集后追加玩家」一致。

### 调用点迁移（22 处，全部生产可达）

| 类别 | 调用点 | 收编形态 |
|---|---|---|
| 纯谓词 | 压力板、绊线、发射器生成占位检查 | `has_*` 早退**零分配** |
| 计数/判定 | 测重压力板、探测铁轨、刷怪笼 | `with_*` 暂存就地 `len`/`any`/`count` |
| 迭代消费 | 漏斗、漏斗矿车、活塞、比较器、发射器（剪羊毛/装备）、实体推挤×5、掉落物合并、弹射物×4、唤魔者尖牙 | `with_*` 暂存闭包迭代 |
| 联合查询 | 区域效果云、潜影弹、喷溅药水×2、发射器装备 | `with_entities_and_players_at_box` 单缓冲 |

**关键设计点：**

- **早退语义化**：`return true`/`return None` 类调用点改闭包返回
  `bool`/标志位，外层承接，控制流逐点等价（漏斗拾取、剪羊毛、
  装备、浮漂挂钩、比较器展示框裁决）。
- **逃逸数据显式克隆**：喷溅药水/区域效果云的命中集需跨查询存活
  （插件事件可裁剪整批），闭包内 `Arc::clone` 收集逃逸——逐事件
  语义分配保留，逐 tick 容器分配消去。
- **线程安全**：暂存为线程局部，rayon 并行 tick（实体批/方块实体批/
  计划刻批）各工作线程持一份；消费闭包不回调本查询族，无
  `RefCell` 二次借用路径。活塞推动实体的 `move_entity`、发射器
  `drop_at` 等消费内动作均不触发按盒查询。
- **未迁移清单（刻意保留分配版）**：插件 WASM API（ABI 边界需所有权
  返回）、物品放置（盔甲架/船/末影水晶等，逐使用事件）、AI 目标
  （献花/袭击寻路/复仇，低频）、唤魔者/劫掠者/村民/猪灵/凋灵
  （技能施放，逐事件）、拴绳结（加载路径）。均为冷路径或语义
  必需，不属于流失。

## 3. 兼容性论证（红线 2）

- **行为逐元素全等**：基准对两形态的「候选内容、谓词结果」双指纹
  FNV-1a 逐元素比对，**全等**；生产侧桶索引去重（`Arc::ptr_eq`）、
  死引用剔除、空桶清理、大盒回退逻辑一行未动。
- **无功能丢失**：命中集内容/顺序（联合查询实体在前玩家在后）、
  谓词真假、插件事件触发点与可取消语义、拾取/剪羊毛/装备的成功
  早退行为均未变。
- **无内存驻留膨胀**：暂存容量上界即历史峰值命中数，与旧实现每次
  grow 到的容量相同。

## 4. 基准结果

负载：600 tick ×（3000 实体盒查询 + 400 玩家盒查询 + 500 谓词查询，
单次命中 0-8）。

| 形态 | 分配次数 | 分配字节 | 每 tick 分配 | 每 tick 字节 |
|---|---|---|---|---|
| 逐调用新建（现状） | 2,959,400 次 | 242,742,400 B | 4,932.3 次 | 404,571 B |
| 复用+谓词早退（本轮） | **0 次** | **0 B** | 0.00 次 | **0 B** |

- **稳态零分配**：复用形态热身 tick 后整个 600 tick 测量窗零分配。
- **每 tick 消去约 395 KiB / 4932 次分配**——迄今单轮最大（轮次 16
  为 340 KiB/2140 次）。以 20 Hz 计每世界每秒消去约 7.9 MiB 临时
  分配，漏斗与实体密度越高收益越大。
- **内容门全等**：候选内容与谓词结果指纹逐元素一致。

## 5. 测试与门禁

- 行为等价由基准双指纹门（候选内容 + 谓词结果）兜底；`entity_index`
  既有单测（桶区间/反向区间/超距回退）经 `query` 薄包装原样通过。
- 门禁：`papokin` 407 测试全绿；`cargo clippy --workspace
  --all-targets` 零告警。

## 6. 结论

本轮把复用形态推广到**按盒空间查询**这一全仓最高频的逐调用分配
点：基础设施层 `query_into` 重填 + `retain` 原地过滤（单缓冲化）、
谓词早退（`has_*` 零分配）、线程局部暂存 + 闭包门面三件套，迁移
22 处每 tick 热路径调用点，每 tick 约 395 KiB / 4932 次分配流失
收编为稳态零分配，行为逐元素全等。配合轮次 14-16，tick 主循环、
实体 tick、方块实体 tick、红石刻四大执行域的常态分配面全部肃清。
