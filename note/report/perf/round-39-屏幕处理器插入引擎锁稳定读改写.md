# 轮次 39 · 屏幕处理器插入引擎锁稳定读改写：`insert_item` 两段锁克隆 → `Slot::with_stack_mut` 原位 RMW

## 背景：在册候选的评估落地

轮次 38 挂账的「屏幕处理器事务引擎（screen_handler.rs 移动/合并
/shift-click 核心路径）克隆-改写-`set_stack` 形态——跨槽事务回滚
语义在原位改写下如何表达」在本轮评估并收口。

评估结论：**引擎的提交粒度本就是逐槽的**（原代码每命中一个槽即
`set_stack` 提交，跨槽间无原子性、也无回滚——点击级串行化由轮
早期落位的「跨玩家竞态条带锁」承担），因此原位改写无需表达跨槽
回滚——每槽一个锁稳定 RMW 即是与原语义逐位等价的最小改写；
真正的快照对调（Swap/光标交换）与收纳袋拦截簇显式豁免（见后）。

调用面：`insert_item` 为 **18 个屏幕处理器共用**（通用箱子、合
成、熔炉系、商人、铁砧、织布机、锻造、切石、附魔、酿造、信标、
驮兽、地图台、砂轮、石切、GUI 构建器……），每次 shift-click /
结果取出跑两趟扫描（合并趟 + 空槽趟），最多触及 36+ 槽。

## 改动

### API 演进（两件）

1. **`Inventory::with_stack_mut` 返回 `bool`**（是否提交）：19 个
   覆写与默认回退同步演进；轮 38 调用方以捕获变量聚合、返回值可
   忽略，源码兼容零改动。
2. **`Slot::with_stack_mut`**：默认实现透传
   `inventory.with_stack_mut(index, f)`（19 个物品栏覆写即时惠及
   全部槽位类型）+ 提交时 `mark_dirty`——等价于 `set_stack` 的
   路径（含物品栏侧各自副作用）。回调约束与物品栏侧同源：返回
   `false` 不得改动；回调内不得调用槽位或物品栏的任何方法。

### 引擎迁移（5 处）

| 路径 | 文件 | 收益 |
|---|---|---|
| `insert_item` 合并趟 | screen_handler.rs | 同物合并原位加（零克隆）；**异物/已满槽的整栈克隆白付清零** |
| `insert_item` 空槽趟 | 同上 | 空槽探测借用化；回调内复查空槽后原位置入（split 两臂同付） |
| `can_fully_insert` 预检 | 同上 | 结果取出预检逐槽克隆 → 借用判读（容量计算入回调，`get_max_item_count_for_stack` 为纯配置函数锁内安全） |
| QuickMove 重试环 | 同上 | 续搬判读整栈克隆 → 借用等值比较（大堆多次续搬白付清零） |
| `insert_stack_count` | slot.rs | 光标放置路径 RMW 化（容量上限回调外前置） |

### 逐点语义核对（红线：行为/UX 零变化）

- 合并趟上限外提论证：`get_max_item_count_for_stack` 只依赖物品
  与组件（count 无关）+ 槽位配置；合并分支以
  `are_items_and_components_equal` 保证两栈同物同组件后，以传入
  堆求值与以槽内堆求值恒等；未进入分支时该值不被使用；
- 饱和加减防超堆叠注释（存档 count>64 回绕吞量）逐字保留；
- 空槽趟「回调内复查空槽」：探测与写入之间槽位被并发占用时，
  原代码会以陈旧快照整栈覆盖他方插入（吞物品），新代码保持不动
  ——在点击条带锁串行化的现实下两序等价，并发边角上新序更安全；
- `insert_stack_count` 条件序保持：非空且不同物时不写入（min
  计算为局部值，不触碰传入堆）；
- 重试环折叠序（先 `item_id` 后 `count`）与原探测一致；
- 每轮 `mark_dirty` 触发次数与原 `set_stack`+显式调用双触发一致。

### 豁免（本轮评估后明确不做，记录理由）

| 形态 | 理由 |
|---|---|
| Swap/光标交换簇（:1300+） | 显式快照对调语义（`old = cursor.clone(); *cursor = slot; set_stack(old)`），两栈交错写 + `on_take_item`/装备广播回调后置——原位改写无净收益（交换本质需要两份所有权） |
| 收纳袋三处拦截簇（:1174-1245） | `intercepted` 拦截链与防复制守卫（结果槽排除）交织，低频特性，克隆数每点击 O(1) |
| `try_take_stack_range` | 取出走 `remove_stack_specific`（已是锁内原位 split），残留 `get_cloned_stack` 探测为纯读 + `set_stack_prev` 回调语义 |

## 双臂基准

`benchmark/src/bin/shift_click_insert_rmw.rs`（第 39 个 bin）。
「shift-click 整理」混合轮模型（36 槽区域：6 异物满载 + 4 同物
未满 + 空槽带）：每轮合并趟扫 10 占用槽（旧臂逐槽克隆）→ 空槽
置入（split 两臂同付）→ 重试环 2 次源槽探测（旧臂整栈克隆）；
每 8 轮一次结果取出（`can_fully_insert` 预检 10 槽 + 结果堆合并，
主趟后同物槽已满不早停）；每轮末消费排空回基线（直写脚手架，
两臂同构零分配）。

不可消除。）

## 负面发现与后续清单

- `Inventory::with_stack_mut` 返回 bool 后，轮 38 的
  `add_one_item` 等可改用返回值替代捕获变量（纯风格统一，无
  收益，不动）；
- 屏幕处理器其余快照对调簇为永久豁免（交换语义需要所有权）；
- 剩余在册：装备广播簇（协议层按值入参）、攻击路径「快照-验证-
  提交」分离重构、漏斗 `can_transfer_to` 谓词入参化 RMW。
