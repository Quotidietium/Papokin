# 0.3.36 构建与验证

构建目标为 Windows x64 的 `x86_64-pc-windows-gnullvm`，使用 Rust 1.99 和 LLVM-MinGW UCRT 交叉工具链。仓库使用 Rust，发布产物为 `.exe`，不能替换为 JAR。

验证结果：

- `cargo check --locked -p papokin --tests` 通过。
- 服务端的自然生成 4 项回归、烟花元数据映射 1 项回归通过。
- `cargo test --locked -p papokin-codegen`：9 项全部通过。
- `cargo clippy --locked -p papokin --lib --no-deps` 通过，保留仓库原有弃用和 lint expectation 警告。为兼容当前 Clippy，等价合并蜡烛交互的公共返回值，单独提交。
- `cargo test --locked -p papokin --lib`：418 通过、3 失败。其中遥测测试在允许网络的环境重试通过；另外两项失败位于本次未修改的 `plugin/mod.rs` 和 `net/chunk_sender.rs`。不宣称完整测试套件全绿。
- 未验证 Windows 运行和真实 Minecraft 客户端效果，按用户要求交付可执行文件后由用户实测。

保留的完整测试失败：

1. `plugin::tests::resolve_plugin_file_rejects_traversal_and_non_bare_names`：Linux 路径组件判定接受带反斜杠的名字。
2. `net::chunk_sender::tests::prune_keeps_buckets_within_hysteresis`：部分逐出后 HashMap 报告的可用容量与断言不一致。

发布构建使用：

```sh
CARGO_BUILD_JOBS=1 cargo build --locked --release -p papokin --target x86_64-pc-windows-gnullvm
```

链接器和 C 编译器使用 LLVM-MinGW 的 `x86_64-w64-mingw32-clang`。构建后检查 PE 架构、DLL 依赖及归档校验和；客户端实测项目附于交付包说明。
