## 2. 分层规则（依赖方向约束）

```mermaid
graph TD
    L0["层级 0 · 零件层<br/>codecs · macros · api-macros<br/>host-bindings · plugin-runtime · plugin-wit"]
    L1["层级 1 · 基础库层<br/>nbt → util"]
    L2["层级 2 · 配置/数据层<br/>config · data"]
    L3["层级 3 · 协议/引擎层<br/>protocol · world"]
    L4["层级 4 · 功能框架层<br/>command · inventory · gametest"]
    L5["层级 5 · 应用层<br/>papokin 主 crate"]
    L0 --> L1 --> L2 --> L3 --> L4 --> L5
```

- 依赖只能自上而下（高层依赖低层），**不存在环**——例如 `papokin-world` 不知道 `papokin-protocol` 的存在，方块/区块数据结构因此与网络层解耦。
- 主 crate `papokin` 是唯一同时触及全部层的"组装点"。
- `papokin-macros` 是过程宏（编译期），被 protocol/util/主 crate 共用，不参与运行时依赖环。

## 3. 外部依赖分类（workspace 统一版本）

### 3.1 运行时与并发

| 依赖 | 用途 | 关键使用点 |
|------|------|-----------|
| tokio 1.53 | 异步运行时（网络、IO、定时） | `main.rs:48`，全部 net/ |
| tokio-util | TaskTracker / CancellationToken | `lib.rs:45-46`（任务追踪与停服信号） |
| rayon 1.12 | 数据并行（tick/生成） | `main.rs:55-72` 全局池限容（默认 `(核数/4).clamp(4, 8)`，`PAPOKIN_RAYON_THREADS` 可调），`server/mod.rs` 世界并行 |
| crossbeam 0.8 | SegQueue 无锁队列 | `entity/player.rs:531` 入站包队列 |
| dashmap 6.2 | 并发哈希表 | `Level.loaded_chunks`（`level.rs`） |
| arc-swap 1.9 | 无锁原子换 Arc | `Server.worlds` / `command_dispatcher` |
| futures 0.3 | 组合子 | select/Either |

### 3.2 序列化与数据格式

serde / serde_json / serde_repr / toml（配置）/ postcard（紧凑二进制）/ bytes（零拷贝包负载）。

### 3.3 加密与安全

aes+cfb8（协议流加密，`net/java/login/encryption_response.rs`）、rsa（KeyStore 1024 位，`server/key_store.rs:40`）、ed25519-dalek（插件签名、遥测签名）、sha1/sha2/md5/hmac、rustls(ring)（全树统一 TLS provider，`main.rs:54` 显式安装）。

### 3.4 网络

reqwest(rustls-no-provider)（Mojang API/遥测）、axum+hyper（WASI http 桥）。

### 3.5 插件运行时

wasmtime（**git rev `f6b3140d` 固定**，`Cargo.toml:230`，启用 component-model/async/gc/threads）、wasmtime-wasi(-http)、wit-bindgen 0.61、wasmparser/wasm-encoder（运行时内省与编码）、libloading 0.9（native 插件 dylib 加载）。

### 3.6 其他

flate2/async-compression/lz4-java-wrc/ruzstd（区块 IO 压缩）、tracing 系（日志）、rustyline（控制台）、notify 8.2（插件热重载文件监听）、sysinfo（状态查询）、criterion（bench，papokin-world/nbt/util/data 四 crate 有 benches/）、phf（完美哈希静态表）、num-bigint/crypto-bigint、indexmap、itertools、lru、uuid。

### 3.7 特殊依赖说明

- **wasmtime 固定 rev**：注释（`Cargo.toml:228-229`）说明是为了等待 Component Model sync reentry 的批准实现——与 `papokin-plugin-runtime` 的同步重入机制强相关。
- **`rustls` ring provider 全局唯一**：`main.rs:52-54` 在任何 client 构建前安装 ring provider，与 wasmtime-wasi-http 保持一致。

## 4. feature 依赖：papokin-data 的 ID 重映射体系

`papokin-protocol` 依赖 `papokin-data` 时开启 15 个 `*_id_remap` feature（如 `item_id_remap`、`entity_id_remap`、`sound_id_remap` 等，`crates/papokin-protocol/Cargo.toml`），对应 `generated/` 下的条件编译重映射表（另有 `sync_id_remap` 模块承载登录注册表同步的重映射）。

**用途：存档版本重映射**。这些表服务于 1.21.11 存档重写服务——读写历史版本（26.3）存档与区块时，把方块状态、物品、实体等旧数字 ID 翻译为当前版本 ID，并处理登录注册表同步表的版本漂移，详见 [09-存档系统重写实现记录.md](09-存档系统重写实现记录.md)。

## 5. 依赖体量与风险点

| 观察 | 说明 |
|------|------|
| 最重依赖链 | `papokin → papokin-protocol → papokin-data(generated 67MB)`，编译期体量大但全是静态数据（零运行时成本） |
| git 依赖 | 仅 wasmtime 三件套固定 rev；升级需同步验证插件运行时重入语义 |
| 双许可边界 | `plugin-api`/`plugin-wit` MIT/Apache，其余 GPLv3 —— 插件作者不必开源插件 |
| 循环引用的运行时处理 | `World` 持 `Weak<Server>`（`world/mod.rs:275`）避免 `Arc` 环；`PluginHostState` 持 `Weak<WasmPlugin>` 回链（`state.rs:185-197`） |
| 未用依赖防线 | CI `cargo-machete` 作业强制清查（`rust.yml` machete job） |
